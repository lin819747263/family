🛠 落地说明（原型 → 代码时需要确认的点）

  1. 周 / 自定义区间缺后端接口：现有报表接口只有 daily(year,month)、monthly(year,month)、yearly(year)、yearly-category(year)、yearly-category-matrix(year)，都无法表达任意日期范围。建议新增 GET /accounting/report/range?bookId&startDate&endDate&groupBy=day|month，一次返回收支合计、按日/月序列、按一级+二级分类聚合；否则前端只能拉 getTransactions 全量分页数据自行聚合（跨月周会踩坑，且数据量大）。
  2. 二级分类下钻：周/月/年的二级分类明细目前只有 yearly-category-matrix 提供（且仅按年）。上面的 range 接口需一并返回 children，排行榜的下钻才不用二次请求。
  3. Index.vue 的「报表分析」子标签：按本次决策移除，仅保留跳转入口；同时移除与之重复的每日明细 CSS 条形图、SVG 环图与导出按钮，图表统一改用 ECharts（Report.vue 已引入）。
  4. 年度报告保持独立页面：顶部「年度报告」按钮继续跳 /accounting/annual-report，本页不重复消费习惯 / 成员对比等内容，只保留可跨周期复用的指标条。
  5. 矩阵单元格跳转：现在跳 /accounting?month&categoryId&categoryName，但 Index.vue 只读 month、忽略 categoryId，下钻会失效，需要一并修掉。
  6. 顺带发现的样式缺陷：src/styles/global.css:51-52 暖居主题里写成了 --border: var(--border) / --border-light: var(--border-light)（自引用），默认主题下所有 var(--border) 会失效导致卡片描边消失；其余四套主题正常。本原型已用 wood-light 色值补正。
